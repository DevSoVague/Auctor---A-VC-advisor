**Done:**
- `src/frontier/ingest/dailymed.py`: for each fda row in the store, reads the label's version history from DailyMed (`services/v2/spls/{setid}/history.json`), downloads each version published 2023-01-01 to 2025-12-31 (`getFile.cfm?type=zip&setid=...&version=...`), parses the SPL XML by LOINC section code into the same section names fda.py uses (highlights excerpts left out), and stores each version whose indications mention COPD as another version of the same document: `fda:<application number>`, `version_label` `dailymed-v<n>`, dated by DailyMed's publication date. A version published on the same day as an fda.py row is skipped. Raw XML in `data/fda/dailymed/` (git-ignored).
- `fda.py`: `remove_stale` now deletes only its own `fda-label*` rows, so a rerun keeps the DailyMed versions.
- `structured.py`: market data still comes from fda.py's newest row; a drug's `as_of_date` is now its earliest stored version, so a backtest sees the drug from then on.
- `tests/test_ingest_dailymed.py` (6 tests) with made-up fixtures `dailymed_spl.xml`, `dailymed_history.json`.

**Justification:**
- openFDA serves only the newest label, so all six marketed drugs were dated 2025 and invisible to a 2025-01-01 backtest.
- Versions before 2023 stay out (whiteboard: 2023-2025 only); versions before a drug's COPD approval stay out through the COPD check (e.g. Dupixent before its 2024 COPD indication).
- Not changed: `market_stats` rows stay dated by the CMS release (2025-05-31), so Part D numbers are still invisible before then.
- DailyMed endpoints taken from its web-services help page (history) and a third-party guide (version zip); not yet tried live.
